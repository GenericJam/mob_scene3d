# Scene IR: declarative scene graph + diff/patch semantics

- Date: 2026-08-30
- Status: accepted
- Bead: `mob_scene3d-qh4`
- Code: `lib/mob/scene3d/ir.ex` (structs, typespecs, `validate/1`),
  `lib/mob/scene3d/ir/patch.ex` (`diff/2`, `apply/2`)

## Context

Mob screens hold UI as data in assigns; `render/1` produces a tree, and
`Mob.Sender` — the only process allowed to touch the render NIFs — coalesces
and commits it (`clear_taps → register_tap* → set_root`, one indivisible
sequence; see mob's `decisions/2026-08-28-sender-serialises-render.md`).
Today that commit is a full-tree JSON `set_root`; mob's roadmap direction is
stable node identity + patches. mob_scene3d must fit that shape from day one:
the 3D scene is data in assigns, entities have stable ids, and what crosses
the NIF wire is a *patch*, not a scene resend — a 3D scene re-uploads
gigabyte-class GPU state if you get this wrong, so patches are not an
optimization here, they are the design.

This record fixes the IR: entity model, coordinate/unit conventions, what is
structural vs per-frame, the patch grammar and its ordering guarantees, the
animation and event surfaces, the error taxonomy, version-skew posture, and
the introspection contract. The native applier lane (`mob_scene3d-nhf`)
implements from the Filament mapping table at the bottom.

## Decision

### Entity model

A scene is a **flat map of entities keyed by id**, parenting by reference —
not a nested tree.

```
%IR{entities: %{id => %Entity{id, parent, transform, visible, pickable, data}}}
```

- **Kinds** are carried by the `data` payload, not a redundant tag:
  `%Model{}`, `%Camera{}`, `%Light{}`, `%Environment{}`, or `nil` for a pure
  transform **group**. `IR.kind/1` derives it; two fields describing one fact
  is how intent and readback drift apart.
- **Ids are non-empty strings**, stable across frames. Strings, not atoms:
  Chopaat-style scenes mint ids from data (`"cowrie_17"`), and dynamic atoms
  leak. The component layer (`~MOB` sugar, later bead) may accept atoms but
  normalizes before the IR boundary; `validate/1` rejects anything else. Pick
  events and readback use the same string — identity is never translated.
- **Parenting**: `parent` is an id or `nil` (root). The forest must be
  acyclic and reference-complete; `validate/1` reports `{:unknown_parent,
  id, parent}` and `{:parent_cycle, ids}`. A flat map diffs by key and makes
  reparenting a per-frame op instead of a subtree move.
- **Singletons**: at most one camera and one environment per scene in v1
  (`{:multiple_cameras, ids}` otherwise). Filament renders a `View` through
  one camera and binds one `IndirectLight`/`Skybox` per `Scene`; modelling
  multi-camera now would be speculative API. Multi-camera (cuts, PiP) is an
  extension: an `active` flag plus a caps bump, not a breaking change.
- `visible` toggles rendering without destroying native resources;
  `pickable` opts a **model** into ray picking (`:pickable_requires_model`
  otherwise — picking a light is a category error and errors at validate
  time, not silently never-hits).

### Transforms: TRS, right-handed, +Y up, meters

- **Representation: decomposed TRS**, never a raw matrix. `position` vec3,
  `rotation` unit quaternion `{x, y, z, w}`, `scale` vec3. TRS diffs per
  entity cheaply, interpolates sanely, cannot encode shear, and is exactly
  glTF's node transform. The native applier composes the `mat4f` that
  `TransformManager` wants. `Transform.from_euler/2` is degrees-facing sugar
  (XYZ order, matching glTF/Blender); quaternions are what the IR stores and
  the wire carries. The applier normalizes quaternions; `validate/1` checks
  shape, not unit length (float fuzz across a JSON wire makes exact-norm
  validation a flake generator).
- **Handedness: right-handed, +Y up, -Z forward** (camera and directional
  lights look down local -Z). This is glTF 2.0's convention and Filament's
  native one — the entire asset path (Blender export → `.glb` → gltfio →
  Filament) already speaks it, so the IR adopting anything else would buy a
  conversion layer and a permanent class of mirrored/rotated-asset bugs for
  zero benefit. Documented once, here, per the parity rule; every other doc
  links here.
- **Units: meters**, glTF-native. Filament's photometric lighting units
  (lux/lumens) assume metric scale; IBL intensities in lux only mean
  anything if geometry is in meters. Angles at the API surface are degrees
  (humans author degrees); quaternions on the wire.
- **Colors: linear floats 0.0..1.0**, glTF factor semantics. No sRGB hex at
  the IR layer; the component layer may offer sugar later.

### Material parameter overrides

A sparse per-entity override of glTF-authored PBR factors, applied to every
material instance of the model's asset:

```
%Material{base_color: {r,g,b,a} | nil, metallic: 0..1 | nil,
          roughness: 0..1 | nil, emissive: {r,g,b} | nil}
```

`nil` means "keep what the asset authored" — an override is a tint, not a
material definition. This subset is exactly what Chopaat piece tinting needs
(base color per player, emissive for selection highlight) and maps 1:1 onto
gltfio's standard `MaterialInstance` parameters, so the applier has no
translation table to get wrong.

**Extension mechanism**: new parameters are new struct fields plus a native
caps bump (see version skew) — never a free-form `params: %{}` map. Unknown
keys that native silently drops are the phantom-`:ok` failure mode (mob #80)
wearing a materials costume. Per-primitive targeting (override only material
slot N) is a foreseen extension: `target: :all` default field, same
mechanism.

### Structural vs per-frame

**Structural** = the native applier must create/destroy resources:

| Change | Why structural |
|---|---|
| entity add / remove | entity + component creation, asset instancing |
| entity kind (data module) change | different native components entirely |
| `Model.asset` | new gltfio asset instance |
| `Light.type` | Filament fixes light type in `LightManager::Builder` |
| `Environment.ibl` / `.skybox` | KTX load, new `IndirectLight`/`Skybox` |

**Per-frame** = cheap state pokes, expected every frame: transforms,
visibility, pickability, parenting, material overrides, all camera params
(fov/near/far), light intensity/color/shadows/cone, environment intensity,
animation state.

The grammar encodes the split: structural changes to an existing id travel
as `{:replace_entity, entity}` (destroy + recreate, id persists, children
untouched), and `apply/2` **errors** on a per-frame op smuggling a
structural change (`{:structural_field, id, :light_type}`) rather than
letting an applier guess.

### Patch grammar

Defined and locked by `Mob.Scene3d.IR.Patch` — `diff/2` computes it,
`apply/2` is the executable reference the native applier must agree with,
and the property `apply(a, diff(a, b)) == {:ok, b}` holds over generated
scenes (property-tested now, with zero native code).

Ops:

```
{:add_entity, entity}            {:set_parent, id, parent | nil}
{:replace_entity, entity}        {:set_transform, id, transform}
{:remove_entity, id}             {:set_visible, id, bool}
                                 {:set_pickable, id, bool}
{:set_material, id, material|nil}   {:set_camera, id, camera}
{:set_animation, id, anim|nil}      {:set_light, id, light}
                                    {:set_environment, id, environment}
```

Setters carry **whole values, not merges** — replace semantics are
idempotent and leave no "which fields did this touch" ambiguity between the
Elixir reference and the native applier.

**Canonical order** within a patch (emitted by `diff/2`, enforced by
`apply/2` erroring on dangling references):

1. adds, parents-first
2. replaces, parents-first
3. reparents
4. removals, children-first
5. per-frame ops, by id

Adds precede reparents so survivors can move under new entities; reparents
precede removals so survivors can leave a dying parent before it goes.

**Batching + ordering relative to mob's frame commits.** One patch = one
frame, applied atomically (native rejects the whole patch on any error —
no partially applied frames observable, ever). Patches ride the existing
commit discipline rather than inventing a second one:

- The `Scene3d` viewport is an ordinary node in the 2D tree (like
  `gpu_view`: id, width/height, handlers). Its placement commits via
  `set_root` as today.
- Scene *content* does not ride the 2D JSON. The screen's render produces
  the scene IR in assigns; the diff against the **last committed IR** for
  that viewport id becomes one `scene3d_apply(viewport_id, patch)` NIF
  call, made from `Mob.Sender`'s `commit/1` — the same single process,
  same coalescing (three re-renders before flush = one diff/one patch,
  computed against what was actually committed, not against dropped
  intents), same activation gating (#103 reservation / #111 activation
  token semantics apply unchanged: a patch produced by a screen that was
  parked at render time is dropped exactly like its 2D tree).
- Ordering guarantee: the scene3d patch for a frame is applied in the same
  sender commit as that frame's 2D tree — an agent that observes the new
  2D frame may assume the scene patch landed (or the commit errored
  loudly). `Mob.Sender.sync/1` covers 3D for free.
- First commit for a viewport id is `diff(IR.empty(), ir)` — the bootstrap
  is the same grammar, not a special full-upload path. Viewport teardown
  (screen gone) destroys the native scene wholesale; no ops needed.

Wire encoding (for the `nhf` lane): the Elixir-side grammar above is
canonical; the wire is a versioned JSON array of op arrays, same
`:json.encode` path the renderer already uses. Field-level wire layout is
the applier lane's to fix — against `apply/2`'s behaviour, which is the
contract.

### Animation control surface

Everything is **declarative state, not commands** — the one place a scene
API usually goes imperative, and deliberately not here:

```
%Animation{name, play_id, loop: false, speed: 1.0, paused: false, seek: nil}
```

- Set `animation:` on a model → the diff emits `{:set_animation, id, anim}`
  → the applier starts the named glTF clip. **Replay is a `play_id`
  change**: same clip, new `play_id`, and the applier restarts it. "Play"
  is thus a pure assign update, replayable and coalescing-safe like every
  other Mob state change; there is no `play/2` NIF for a screen to call
  around the sender.
- `paused` freezes the clip clock; `speed` scales it; `seek` (seconds,
  absolute) repositions without restarting; `loop` self-explains. Pause /
  seek / resume are field updates on the same struct.
- **Completion**: when a non-looping clip finishes, native delivers
  `{:animation_done, play_id}` to the owning screen process. This is the
  Chopaat contract (bead `mob_scene3d-al6`): rules engine rolls → screen
  sets `%Animation{name: "tumble_4", play_id: roll_uuid}` → on
  `{:animation_done, roll_uuid}` the agent reads `scene/1` and asserts the
  settled cowrie orientations match the rolled value. `play_id` is the
  correlation token; names alone can't distinguish two throws of the same
  tumble.
- Readback (`scene/1`) exposes per-model animation state: clip name,
  `play_id`, current time, playing/paused/done — so an agent can assert
  playback without a screen recording (recordings remain the acceptance
  evidence for *motion quality*, per AGENTS.md).
- Unknown clip name: `{:error, {:unknown_animation, id, name}}` surfaced as
  a scene error event at apply time — never a silently idle model.

### Events surface

- `{:pick, entity_id}` — delivered to the screen process that owns the
  viewport when a tap lands on a `pickable` model, resolved by native ray
  pick. The registration shape follows `Mob.UI`'s handler convention
  (`on_pick: {pid, tag}` on the `Scene3d` viewport node, wired through the
  same tap-table/`Mob.Listener` path as `on_tap`); the message carries the
  entity id string. A tap inside the viewport that hits nothing is **not**
  an event — misses are a query result (`pick/3` below), not noise pushed
  at the screen.
- `{:animation_done, play_id}` — as above.
- `{:scene3d_error, viewport_id, error}` — async native failures (asset
  load, patch rejection detected after the cast) so a screen is never left
  believing a phantom `:ok`.

### Error taxonomy

Honest errors per AGENTS.md — never a silent no-op, never a phantom `:ok`.
Symmetric between the pure reference (`Patch.apply/2` returns these today)
and the native applier (must return the same terms over the wire):

| Error | Meaning |
|---|---|
| `{:duplicate_entity, id}` | add of an existing id |
| `{:unknown_entity, id}` | any op against a missing id |
| `{:unknown_parent, id, parent}` | add/replace/reparent to a missing parent |
| `{:has_children, id}` | remove before removing/reparenting children |
| `{:kind_mismatch, id, kind}` | per-frame op against the wrong kind |
| `{:structural_field, id, field}` | structural change smuggled in a setter |
| `{:unknown_op, op}` | grammar the applier doesn't speak (see skew) |
| `{:invalid_result, reason}` | grammar-legal ops producing an invalid scene |
| `{:bad_asset, ref, reason}` | asset missing/unparseable (async, native) |
| `{:unknown_animation, id, name}` | clip name not in the asset (native) |
| `{:no_entity_at_point, x, y}` | `pick/3` miss — a result, not a crash |

Validation errors (`IR.validate/1`) are their own family
(`{:invalid_entity, id, reason}`, `{:parent_cycle, ids}`, …) and fire
Elixir-side before anything reaches a wire.

### Version skew

The precedent is mob #111: during a hot code push, modules (and here, an
Elixir library vs an older native applier) upgrade independently; you enter
a new protocol only once every participant provably speaks it.

- The native side exposes `scene3d_caps/0` → `%{schema: n, ops: [...]}`.
  The Elixir side consults it (guarded by `function_exported?`-style checks
  on the NIF stub, exactly the #111 shape) before emitting anything beyond
  the v1 op set.
- A feature needing an op the applier doesn't declare returns
  `{:error, {:unsupported, feature, needs: version}}` at the API surface —
  degraded loudly, never silently.
- Defense in depth: an old applier receiving an unknown op anyway (skew
  races the caps check) rejects the **whole patch** with
  `{:unknown_op, op}` — atomicity holds, the scene stays at its last good
  frame, and the error event reaches the screen. `Patch.apply/2` implements
  this exact behaviour so the fallback path is property-tested too.
- New ops are additive; existing op semantics never change meaning
  (that would be a schema bump, i.e. a new major).

### Introspection contract

`Mob.Scene3d.scene(node)` returns the **applied scene read back from
native** — the applier's own registry, world transforms from
`TransformManager`, animation clocks, asset load status — *not* the Elixir
intent echoed back. Divergence detection is the point: an agent holding the
intended IR compares it against `scene/1` and any mismatch is, by
construction, a bug in the wire/applier (or a skew condition), which is
exactly what the readback exists to catch. Echoing intent would make the
introspection layer incapable of detecting the only failures it exists to
detect (the lesson behind `element_frames`/`sample_region`: read the truth
from the platform side).

- `scene/1` shape mirrors the IR (same ids, same field names) plus
  native-only truth: world transform per entity, animation time/status,
  per-entity `status: :ready | :loading | {:error, reason}` for assets.
- `Mob.Scene3d.pick(node, x, y)` → `{:ok, entity_id} |
  {:error, {:no_entity_at_point, x, y}}` — the 3D analogue of
  `tap_id`/`find`, same native ray pick the `{:pick, id}` event uses, so
  test-time picking and runtime picking can't disagree.
- Naming and calling conventions follow `Mob.Test` (node-first args,
  `%{id => value}` maps like `element_frames/1`); pixel truth reuses mob's
  existing `sample_region` — no parallel screenshot machinery.
- These are feature gates, not conveniences: per AGENTS.md, no rendering
  feature in this repo merges without its introspection counterpart.

### Filament mapping (for the applier lane, `mob_scene3d-nhf`)

| IR concept | Filament counterpart |
|---|---|
| entity id (string) | `utils::Entity` via `EntityManager`; applier owns the `id ↔ Entity` map (and the reverse map picking needs) |
| group / `parent` | `TransformManager` instance; `setParent(child, parent)` |
| `Transform` (TRS) | compose `mat4f` = T·R·S → `TransformManager::setTransform` (local); world transforms read back via `getWorldTransform` for `scene/1` |
| `Model.asset` | gltfio `AssetLoader` → `FilamentAsset`; repeated refs share one asset via `createInstance` (`FilamentInstance` per IR entity); instance root parented under the IR entity's transform node |
| `Material` override | `FilamentInstance::getMaterialInstances()` → `setParameter("baseColorFactor" / "metallicFactor" / "roughnessFactor" / "emissiveFactor", …)` on each |
| `visible` | `Scene::addEntity` / `Scene::remove` of the instance's renderables (resources stay alive) |
| `pickable` | membership in the applier's pick set; hit renderable → walk up instance to asset root → IR id |
| `Camera` | `Engine::createCamera(entity)`; `setProjection(fov_y, aspect, near, far)` with aspect from the viewport; pose from the entity's transform; `View::setCamera` |
| `Light` | `LightManager::Builder(type)` — type fixed at build (hence structural); intensity/color/shadow/cone via `LightManager` setters |
| `Environment.ibl` | `ktxreader` → `IndirectLight` (prefiltered specular + SH irradiance from `cmgen`); `Scene::setIndirectLight` |
| `Environment.skybox` | `ktxreader` → `Skybox`; `Scene::setSkybox` |
| `Animation` | gltfio `Animator`; name→index resolved at asset load; per-vsync `applyAnimation(index, t)` with `t` driven from `play_id`/`speed`/`paused`/`seek` state; completion detection = `t >= getAnimationDuration && !loop` → `{:animation_done, play_id}` |
| `{:pick, id}` / `pick/3` | `View::pick(x, y, callback)` (async GPU pick) → reverse-map renderable → id |
| patch atomicity | validate whole patch against the applier registry before touching Filament state; ops touch `Engine` objects only after the dry-run passes |

## Consequences

- The patch grammar is executable and property-locked before any native
  code exists; the `nhf` lane implements against `Patch.apply/2`'s observable
  behaviour and the table above, not prose.
- Whole-value setters trade a few redundant bytes per op for
  merge-ambiguity-free semantics; at 3D-scene op sizes (a TRS is 10 floats)
  this is noise next to the asset traffic it replaces.
- Diff-against-last-committed requires `Mob.Sender` (or the scene3d shim
  around it) to retain the last committed IR per viewport — a small,
  bounded cache; the alternative (diff against last *intent*) silently
  corrupts after any dropped/coalesced frame.
- The v1 singletons (one camera, one environment) and `pickable`-on-models
  keep the applier small; each has a named, additive extension path.
- `Animation.seek` while playing is applier-racy by nature (the clock
  advances between diff and apply); the readback exposes actual time, so
  tests assert against truth. Frame-exact scrubbing is out of scope for v1.
- Open (owner ruling wanted, none blocks `nhf`):
  1. Event tag shape — `{:pick, id}` as specified here vs. mob's
     `{pid, tag}`-parameterised messages (`{tag, id}`) as `on_dismiss`
     does; this record follows the bead spec, the component-layer bead
     should confirm against `Mob.UI` conventions.
  2. Whether `scene/1` lives under `Mob.Scene3d` (as README sketches) or
     also gets a `Mob.Test`-side alias for symmetry with `element_frames`.
  3. Asset-ref root: `priv/scene3d_assets/` assumed here; the asset
     pipeline bead (`mob_scene3d-392`) owns the final layout + plugin
     asset-root interaction (`Mob.Plugins` precedent).

## Post-review rulings (coordinator, 2026-08-30)

1. **Pick events follow mob's configurable-tag grammar**: the Scene3d surface
   takes `on_pick: tag` and delivers `{tag, entity_id}` to the owning screen's
   `handle_info/2` (e.g. `{:piece_picked, "pawn_red_2"}`), defaulting to
   `:pick` when unspecified — so bare `{:pick, id}` remains the out-of-box
   shape while scenes with multiple concerns can namespace. Matches mob's
   `on_tap`/`on_dismiss` precedent; avoids every pick in an app colliding on
   one atom.
2. **Yes to the `Mob.Test`-side alias**: `Mob.Test.scene/1` (and `pick/3`)
   delegate to the plugin so agents drive 2D and 3D through one namespace,
   mirroring `element_frames/1` symmetry.
3. **Asset-ref root defers to the asset-pipeline bead** (`mob_scene3d-392`)
   as proposed; `priv/scene3d_assets/` stands as the working assumption.
